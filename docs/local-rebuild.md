# Local rebuild and measurement of the adviser snapshot

This is the issue #2 phase-5 **documented local rebuild** route. The SQLite
database is generated from the pinned CTW-data source and stays under ignored
`work/`; it is not committed as a binary. The manifest includes the completed
database's streamed SHA-256, byte count, exact adviser and source commits,
source contract fingerprint, SQLite snapshot identity, build time, runtime and
build access plans. A receiver should copy the database and its matching manifest
together and verify them before use. Ordinary queries do not scan or hash the
entire database: hashing is a one-time packaging and verification step.

## Prerequisites and commands

Python 3.11+ with SQLite 3.37+ and Git are required. These commands use only the
Python standard library. Run them from the CTW-adviser repository root. Obtain a
CTW-data checkout or export at the `source_lock.json` commit
`595e22764b22e748afdbafafcb0a6258973e2451` in a sibling directory named
`CTW-data`. The verifier checks the exact locked files and owner scope; a Git
checkout label by itself does not establish matching bytes. On Windows PowerShell:

```powershell
python --version
python -c "import sqlite3; print(sqlite3.sqlite_version)"
python scripts/verify_sources.py --ctw-root ../CTW-data
python scripts/validate_packets.py --ctw-root ../CTW-data
python scripts/rebuild_release.py --ctw-root ../CTW-data --output work/adviser.sqlite --manifest work/adviser.manifest.json
python scripts/verify_release.py --db work/adviser.sqlite --manifest work/adviser.manifest.json
python scripts/build_snapshot.py inspect work/adviser.sqlite
python scripts/query_snapshot.py unit --db work/adviser.sqlite "Lothern Sea Guard"
python scripts/query_snapshot.py matchup --db work/adviser.sqlite "Lothern Sea Guard" "Blue Horrors of Tzeentch"
python scripts/audit_queries.py --db work/adviser.sqlite --ctw-root ../CTW-data --output work/query-audit.json
python scripts/benchmark_packets.py --db work/adviser.sqlite --output work/packet-benchmark.json
```

On Linux or macOS, use the same commands with `python3` in place of `python`.
The paths use forward slashes on all three platforms. Windows was executed for
this record; the Linux/macOS commands are specified but were not run here.
`rebuild_release.py` invokes the same atomic builder as `build_snapshot.py`.
The source verifier runs before import, after reading and before installation.
The manifest is written only after successful build and read-only integrity and
foreign-key inspection. A failed build does not certify an artifact. Run
`verify_release.py` before using a copied pair; it rejects name, size, hash,
unsupported store schema/import contract, foreign-key/integrity errors, and
manifest metadata that differs from the database or this checkout's pinned
source. It also requires a clean-build manifest and compares the adviser commit
to this checkout's HEAD by default. To check against a separately verified
revision, pass `--expected-adviser-commit` with its full SHA. The manifest is
not a signature or an engine-truth certificate. Build time, operating-system
description and query-plan text are descriptive measurements: their types and
shape are checked, but the verifier cannot independently reconstruct the
original build environment or authenticate authorship.

Use `query_snapshot.py passive --db work/adviser.sqlite --include-documentation
KEY` to request the separately attributed research documentation. Default
packets keep evidence IDs and compact explanation text; full provenance and
documentation are opt-in. `docs/lookup-contract.md` defines packet 1.20.0,
semantic qualifications and the inspection site's collapsed source-documentation
panel. The inspection deployment is a separate branch/service and must be
checked against the merged artifact before claiming site parity.

## Measurement method and acceptance limits

`audit_queries.py` traverses all original unit keys with expanded provenance,
checks the packet schema and source locators, records startup/latency, expanded
packet bytes and representative `EXPLAIN QUERY PLAN` output. It is a validation
pass with cached source rows, so its timings are not isolated service latency.
`benchmark_packets.py` uses a fixed 12-single/3-pair set, 25 warm repetitions
per case by default, and compact UTF-8 serialization. It also times one new
connection per case; neither path clears the OS file cache. It measures Python
heap peak for one Daemon Prince request; this excludes SQLite native allocations
and process RSS. The full JSON reports live in ignored `work/` and can be
regenerated by the commands above. Hardware, CPU load and runtime affect times.

The issue's provisional per-case 100 ms warm-median target must retain its
accepted Daemon Prince exception. Do not silently label that target passed or
shorten the packet by dropping source or timing qualifications. Packet bytes are
UTF-8 encoded JSON, not named-tokenizer token counts; no token estimate is
claimed. These measurements characterize retrieval, not source correctness or
combat runtime semantics.
